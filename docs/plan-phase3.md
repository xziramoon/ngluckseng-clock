### 2.2 เนื้อหาบล็อก (API ที่ต้องสร้าง)

```

const STALE_MS = 16 * 3600 * 1000;            // ย้ายมาจากนอกบล็อก ค่าเดิม ต้องตรงกับ 57600000 ใน rules
const TYPE_ORDER = { in: 0, break_start: 1, break_end: 2, out: 3 };
const isExcluded = (l) => !!l && (l.voided === true || l.review === 'rejected');
const bkkDateOf = (ms) => new Date(ms + BKK_OFFSET_MS).toISOString().slice(0, 10);   // = bangkokDate() เดิม (ไทยไม่มี DST)
const hhmmOf = (ms) => new Date(ms + BKK_OFFSET_MS).toISOString().slice(11, 16);
const tsOf = (d, hhmm, plusDay) => Date.parse(d + 'T' + hhmm + ':00+07:00') + (plusDay ? DAY_MS : 0);
const addDaysKey = (d, n) => bkkDateOf(Date.parse(d + 'T12:00:00+07:00') + n * DAY_MS);
const floorMin = (ts) => Math.floor(ts / MIN_MS);
const logsToList = (obj) => ...เหมือน master เดิม (กรอง object, ใส่ id, เรียง ts แล้ว TYPE_ORDER)
function summarize(logsObj) { ...v3... }
function dayReport(d, logsObj, ctx) { ... }
```

**summarize v3** = โค้ด master v2 ปัจจุบัน (บรรทัด 376-390) เพิ่มใน segment: `{ n, inTs, inLog, outTs, outLog, breakMs, breaks: [[startTs, endTs], ...], openBreak, openBreakAtOut }`
- `n` = ลำดับกะ 1, 2, ...; `openBreakAtOut` = true ถ้าเจอ `out` ขณะ `openBreak != null` (rules/validateSeq ไม่ยอมให้เกิด แต่ข้อมูลเก่า/แก้มืออาจมี)
- ผลลัพธ์ระดับบนเหมือน v2 ทุกตัว (`ev, segments, flags, inTs, outTs, breakMs, openBreak, netMs`) โค้ดเดิมที่เรียกใช้ไม่ต้องแก้
- `clock.html` ได้ `inLog/outLog` เพิ่ม (ไม่กระทบการแสดงผล)

**dayReport(d, logsObj, ctx)** สรุป 1 คน × 1 วันทำงาน ใช้ทั้งรายงาน, CSV, บันทึกเวลา, สถานะวันนี้, แอปพนักงาน

`ctx = { shiftStart, graceMin, homeBranchId, breakLimitFor(branchId) → number|undefined, state, now }`


## 3. นิยามรายงานและสูตร

สัญลักษณ์: ⌊t⌋ = `floorMin(t)`; "รายการที่นับ" = log ที่ `ts` เป็นตัวเลขและ `!isExcluded`; "วัน" ทุกที่คือ **วันทำงาน (workDate = key ของ logs)** ไม่ใช่วันตามปฏิทินของเวลาที่กด

### 3.1 ต่อกะ (segment)
| ค่า | สูตร |
|---|---|
| เข้า | `inTs` ของ `in` ที่เริ่ม segment แสดง HH:MM เวลาไทย; `inPlus` = `bkkDateOf(inTs) > d` (เข้าหลังเที่ยงคืนภายในผ่อนผัน แสดง "(+1)") |
| ออก | `outTs` ตาม summarize เดิม (`out` ตัวหลังทับตัวก่อนใน segment เดียวกัน); `outPlus` = `bkkDateOf(outTs) > d` |
| พักของกะ | `breakMin = Σ (⌊end⌋ − ⌊start⌋)` เฉพาะคู่ break_start→break_end ที่จบแล้ว (พักที่ยังไม่กลับไม่นับ) |
| สุทธิของกะ | ปิดแล้ว: `netMin = ⌊outTs⌋ − ⌊inTs⌋ − breakMin`; ยังไม่ปิด: `null` |
| status | `closed` ถ้ามี out; ไม่อย่างนั้น `live` ถ้าเป็นกะสุดท้ายของวัน และ `ctx.state.workDate === d` และ status เป็น working/on_break และ `now − state.inAt ≤ STALE_MS`; นอกนั้น `missing` |

### 3.2 ต่อวัน (คน × workDate)
| ค่า | สูตร |
|---|---|
| ชม.สุทธิ | `netMin = Σ netMin ของกะที่ปิด` แสดง "8 ชม. 05 น." (fmtMin เดิม); ใน CSV เป็นนาทีเต็ม + `(netMin/60).toFixed(2)` |
| พักรวม (ยอดที่รวมเข้ารายงาน) | `breakMin = Σ breakMin ของกะที่ปิด` |
| พักรวมทุกกะ | `breakMinAll = Σ breakMin ทุกกะ` |
| มาสาย | ใช้ `in` ของกะแรกเท่านั้น: `lateRawMin = ⌊(firstInTs − tsOf(d, shiftStart)) / 60000⌋`; `isLate = lateRawMin > graceMin`; `lateMin = isLate ? lateRawMin : 0`; shiftStart ไม่ตรง `^([01]\d|2[0-3]):[0-5]\d$` → `null` (ไม่นับ) · `graceMin = settings.lateGraceMin ?? 5` |
| พักเกิน | `breakLimitMin = Number(branches[branchId].breakLimitMin)` ถ้าไม่ใช่ตัวเลขจำกัด → 60; `isOverBreak = breakMinAll > breakLimitMin`; `overBreakMin = isOverBreak ? breakMinAll − breakLimitMin : 0` |
| สาขาของวัน | `branchId` ของ `in` แรกที่นับ ถ้าไม่มีใช้ `staff.branchId` (เหมือนตัวกรองสาขาของบันทึกเวลา); `multiBranch` = log ที่นับมีมากกว่า 1 สาขา |
| ยืนยันแล้ว | `days[d][sid].confirmed === true` |

### 3.3 ต่อคน (รวมช่วงที่เลือก หลังกรองสาขา/เฉพาะยืนยันแล้ว)
| คอลัมน์ | สูตร |
|---|---|
| วันทำงาน | จำนวนวันที่ `worked` |
| วันครบ | จำนวนวันที่ `worked && openStatus === null` |
| ไม่มีเวลาออก | จำนวนวันที่ `openStatus === 'missing'` |
| กำลังทำงาน | จำนวนวันที่ `openStatus === 'live'` (ปกติ 0 หรือ 1 = วันนี้) |
| ชม.สุทธิ | `Σ netMin` (รวมเป็นนาทีก่อน แล้วค่อยแปลงเป็นชั่วโมง ไม่รวมค่าที่ปัดแล้ว) |
| พักรวม | `Σ breakMin` |
| มาสาย ครั้ง / นาที | `Σ isLate` / `Σ lateMin` |
| พักเกิน ครั้ง / นาที | `Σ isOverBreak` / `Σ overBreakMin` |
| ยังไม่ยืนยัน | จำนวนวันที่ `worked && !confirmed` |
| มีรายการรอตรวจ | จำนวนวันที่ `flagsPending.size > 0` |

### 3.4 กรณีพิเศษ (edge cases)
| กรณี | ผล |
|---|---|
| log `voided` หรือ `review: 'rejected'` | ไม่นับเลย (summarize ตัดทิ้ง) ป้าย "มีรายการไม่นับ" |
| ✘ ไม่ยืนยัน `in` แต่ break/out ยังอยู่ | รายการก่อน `in` ที่นับตัวแรกถูกข้าม (summarize `if (!cur) continue`) ถ้าไม่มี `in` ที่นับเลย → `worked = false` |
| ไม่มีเวลาออก (ลืมออก, STALE) | `status = 'missing'` สุทธิ/พักของกะนั้นไม่นับ แถวรายวันแสดง "ไม่มีเวลาออก" คลิกไปแก้ในบันทึกเวลาได้; มาสายยังนับ |
| กะที่กำลังทำ (วันนี้) | `status = 'live'` แสดง "กำลังทำงาน (ยังไม่นับ)" อัปเดตสดเพราะ `D.logsWin` เป็น listener |
| STALE แล้วกดเข้าวันใหม่ | กะเก่า = missing ใน workDate เก่า กะใหม่อยู่ใน workDate ใหม่ ไม่ซ้อนกัน |
| หลายกะในวันเดียว | แต่ละกะคิดแยกแล้วรวม; ช่วงห่างระหว่างกะไม่นับเป็นงานหรือพัก; สายจากกะแรกเท่านั้น; CSV รายวัน 1 แถวต่อกะ (คอลัมน์ "กะที่") |
| ข้ามเที่ยงคืน | ทุก log อยู่ใน workDate ที่เริ่มกะ: เข้า 20:00 ออก 02:00 (+1) = 1 วันทำงานของวันที่เริ่ม; ⌊⌋ คิดบน epoch จึงไม่มีปัญหาข้ามวัน |
| ข้ามเดือน | กะเริ่ม 31 ต.ค. 20:00 ออก 1 พ.ย. 02:00 นับทั้งหมดในเดือน ต.ค. (ตามวันเริ่มกะ) |
| ขอบเดือน/timezone | ช่วงวันคือ key string `YYYY-MM-DD`; เดือน = `YYYY-MM-01` ถึงวันสุดท้าย (`new Date(Date.UTC(y, m, 0)).getUTCDate()`); ไม่มีการคำนวณด้วย timezone ของ PC (tsOf +07:00 ตายตัว, bkkDateOf/hhmmOf บวก 7 ชม.) |
| วันไม่ตรง (dateMismatch) | นับตาม key ที่บันทึก แต่ติดป้าย "วันไม่ตรง" และแถบเตือน ให้เจ้าของย้ายกะในรอตรวจก่อนสรุป |
| workDate ในอนาคต (เช่น 2099) | อยู่นอกช่วงที่เลือก ไม่ปรากฏ (รอตรวจจับอยู่แล้ว) |
| วันที่ยังไม่ยืนยัน | นับ + แถบเตือน; ติ๊ก "เฉพาะวันที่ยืนยันแล้ว" ตัดแถวที่ไม่ยืนยันก่อนรวม |
| ยืนยันแล้วแต่ยังมีธงไม่ตรวจ | นับตามปกติ (ยืนยัน = เจ้าของรับรอง) ป้าย "รอตรวจ" ยังแสดง |
| พนักงานปิดบัญชีกลางเดือน | `active === false` แต่มีข้อมูลก่อนปิด → แสดงพร้อม "(ปิดบัญชี)"; ติ๊ก "รวมคนที่ปิดบัญชี" **ค่าเริ่มต้นเปิด** ในแท็บรายงาน (ต่างจากบันทึกเวลา); คนปิดบัญชีที่ไม่มีข้อมูลในช่วงไม่แสดง |
| พนักงาน active ที่ไม่มีบันทึกในช่วง | สรุปตามคนแสดงแถว 0 (เห็นว่าไม่มา) รายวันไม่แสดง |
| staff ถูกลบจาก `staff/` แต่ log ยังอยู่ | ชื่อ "(ไม่พบในรายชื่อ) {sid}" เมื่อเลือก "ทุกคน"; ไม่มี shiftStart → ไม่คิดสาย |
| เปลี่ยนสาขาระหว่างวัน | สาขาของวัน = สาขาของ `in` แรก (ใช้กรองและคิดพักเกิน) ป้าย "หลายสาขา" ไม่แยกชั่วโมงตามสาขา (คำถามข้อ 10.6) |
| ค่าตั้งเปลี่ยนย้อนหลัง | shiftStart, breakLimitMin, lateGraceMin ใช้ **ค่าปัจจุบัน** กับทุกวันในอดีต (ไม่มีประวัติค่า) เขียนหมายเหตุใต้รายงาน (คำถามข้อ 10.8) |
| เข้างานคนละช่วงกับกะมาก (กะ 08:00 มาเข้า 20:00) | สาย 720 นาทีตามสูตร เจ้าของเห็นในรายวัน (คำถามข้อ 10.11) |
| shiftStart ใกล้เที่ยงคืน (23:30 แล้วเข้า 00:10) | ร้านไม่มีกะดึก ไม่รองรับพิเศษ: แอปเลือก workDate เป็นวันใหม่ จึงดูเหมือนมาก่อน ไม่นับสาย — บันทึกเป็นข้อจำกัด |
| `out` ขณะยังพัก (`openBreakAtOut`) | พักที่ไม่มีเวลากลับไม่นับ (ตาม summarize เดิม) ป้ายแดง "พักไม่มีเวลากลับ" ให้แก้ในบันทึกเวลา |
| สุทธิติดลบ / กะเกิน 16 ชม. | ป้าย `negativeNet` / `longShift` แต่นับตามสูตร (validateSeq เฟส 2 ป้องกันตอนแก้อยู่แล้ว) |
| วินาที | ตัดวินาทีก่อนลบ: เข้า 08:00:59 ออก 17:00:10 = 540 นาที (ตรงกับ HH:MM ที่เห็น); ต่างจากการคิดแบบ ms ไม่เกิน ±1 นาทีต่อกะ |

## 4. การโหลดข้อมูลและต้นทุน (master)

### 4.1 วิธีโหลด
- ช่วง `[from, to]` แบ่ง 2 ส่วนด้วย `winKey` (วันแรกของหน้าต่าง reviewDays ที่ฟังอยู่แล้ว)
  - `d >= winKey` → `D.logsWin[d]`, `D.days[d]` (มีอยู่แล้ว ไม่อ่านเพิ่ม อัปเดตสด)
  - `d < winKey` → ฟังก์ชันใหม่ `ensureRange(from, toOld)` (`toOld = min(to, addDays(winKey, -1))`): ถ้ายังมีวันในช่วงที่ `T.cache.logs[d] === undefined` → `Promise.all([get(query(A('logs'), orderByKey(), startAt(from), endAt(toOld))), get(query(A('days'), orderByKey(), startAt(from), endAt(toOld)))])` แล้วเติม `T.cache.logs[d]`/`T.cache.days[d]` **ทุกวันในช่วง** (วันที่ไม่มีข้อมูลใส่ `{}`); ระหว่างโหลดบันทึก key ช่วงใน `T.fetching` กันยิงซ้ำ; ล้มเหลว → แสดงข้อผิดพลาด + ปุ่มลองใหม่ (ไม่ใส่ `{}` ปลอม)
- ใช้ `logsFor(d)` / `daysFor(d)` เดิมของบันทึกเวลา (cache เดียวกัน) — ทุกจุดที่แอดมินเขียน (`commitDayChange` ~บรรทัด 598, `unlockDay` ~621, `confirmDays` ~654, ~1432) ล้าง `T.cache` อยู่แล้ว รายงานจึงโหลดใหม่หลังแก้เอง
- ปุ่ม "โหลดใหม่": ลบ `T.cache` ของวันในช่วงแล้ว render ใหม่
- แนะนำ: ให้ `ensureCache` เดิม (get ทีละวัน 2 ครั้ง/วัน) เรียก `ensureRange` แทน (31 วัน: 62 gets → 2)
- ช่วงสูงสุด **92 วัน** (เลือกเดือนเดียวได้เสมอ) เกินแจ้ง "เลือกได้ไม่เกิน 92 วัน"
- รอให้มี `D.staff`, `D.branches`, `D.settings`, `D.state`, `D.days !== null` ก่อน render (แบบ renderTimes)

### 4.2 ประมาณการต้นทุน (Spark: เก็บ 1 GB, ดาวน์โหลด 10 GB/เดือน, เชื่อมต่อพร้อมกัน 100)
| รายการ | ประมาณ |
|---|---|
| log 1 รายการ (app มีพิกัด/ธง) | ~300 B; ที่แอดมินแก้แล้ว ~450 B |
| 1 คน × 1 วัน (4-6 log) | ~1.5-2.5 KB |
| ร้านนี้ 1 เดือน (สมมติ 8 คน × 31 วัน) | ~0.5 MB logs + ~10 KB days |
| เปิด master 1 ครั้ง (หน้าต่าง 31 วันจากเฟส 2 มีอยู่แล้ว) | ~0.5 MB — รายงานเดือนปัจจุบัน **ไม่เพิ่ม** |
| รายงานเดือนก่อน 1 ครั้ง | +~0.5 MB (ใน session เดียวกันไม่อ่านซ้ำ) |
| เจ้าของเปิด master 5 ครั้ง/วัน + ดูเดือนก่อน 10 ครั้ง/เดือน | ~80 MB/เดือน ≈ 0.8% ของโควตา |
| แอปพนักงาน หน้าประวัติ (8 คน × 3 ครั้ง/วัน × 45 KB) | ~32 MB/เดือน |
| พื้นที่เก็บ 1 ปี (logs + audit) | ~10-15 MB ≈ 1.5% ของ 1 GB |

ไม่ต้องสร้าง node สรุปรายเดือน (pre-aggregate) หรือ index เพิ่ม (`orderByKey` ไม่ต้องมี `.indexOn`)

- ☑ รวมคนที่ปิดบัญชี (ค่าเริ่มต้นเปิด) · ☐ เฉพาะวันที่ยืนยันแล้ว

### 5.2 แถบเตือน (เหลือง ใต้ตัวกรอง แสดงเฉพาะที่มี)
- "ยังไม่ยืนยัน N วัน — ตัวเลขอาจเปลี่ยน" (ลิงก์ → บันทึกเวลา ช่วงเดียวกัน ติ๊ก "เฉพาะที่ยังไม่ยืนยัน")
- "ไม่มีเวลาออก N วัน (ไม่นับชั่วโมง)"
- "มีรายการรอตรวจ N วัน" / "คำขอแก้เวลารอ N รายการ" (`D.corrPending` ที่ workDate อยู่ในช่วงและตรงตัวกรองคน)
- "วันไม่ตรง N วัน" (dateMismatch)
- "กำลังโหลดข้อมูลย้อนหลัง..." ระหว่าง `ensureRange`
- หมายเหตุเล็กท้ายหน้า: "คิดสายจากเวลาเข้ากะปัจจุบัน (ผ่อนผัน X นาที) · พักเกินเทียบเวลาพักของสาขาปัจจุบัน · นับเวลาเป็นนาทีเต็ม · กะข้ามคืนนับในวันที่เริ่มกะ"

|---|---|---|---|---|---|---|---|---|

### 5.4 มุมมอง รายวัน
ตาราง 1 แถวต่อกะ เรียงวันที่ (เก่า → ใหม่) แล้วชื่อ

| วันที่ | ชื่อ | สาขา | กะ | เข้า | ออก | พักรวม | สุทธิ | สาย | พักเกิน | สถานะ | ป้าย |
|---|---|---|---|---|---|---|---|---|---|---|---|

- "กะ" แสดงเมื่อวันนั้นมีมากกว่า 1 กะ; สาย/พักเกินอยู่ในแถวกะแรกเท่านั้น
- เวลาหลังเที่ยงคืน "02:00 (+1)" (`fmtT` เดิม)

- คลิกแถว → `gotoTimes(sid, d)` (แก้ในบันทึกเวลา) รายงานเป็นแบบอ่านอย่างเดียว

### 5.5 ปรับหน้าจอเดิมให้ตัวเลขตรงกัน
- บันทึกเวลา: "พักรวม" = `breakMinAll`, "สุทธิ" = `netMin` (จาก `dayReport`) แทน `sum.breakMs`/`sum.netMs`; ป้ายสายใน `tagsFor` ใช้ `dayReport.isLate/lateRawMin`
- สถานะวันนี้: "สุทธิ" ของคนที่ออกแล้วและป้ายสายใช้ `dayReport` (พักที่กำลังพักยังนับสดแบบเดิม)
- แอปพนักงาน ปุ่ม "ออกงานแล้ว": "ทำงาน X · พัก Y" ใช้ `dayReport.netMin`/`breakMin`

## 6. CSV

### 6.1 รูปแบบไฟล์ (ทั้ง 2 แบบ)
- ขึ้นต้นด้วย BOM `﻿` ตามด้วยหัวตาราง 1 บรรทัด แล้วข้อมูล; ขึ้นบรรทัดด้วย `\r\n` (มี `\r\n` ท้ายไฟล์); คั่นด้วย `,`; **ห้าม** ใส่บรรทัด `sep=,`
- `new Blob([text], { type: 'text/csv;charset=utf-8' })` + `<a download>` + `URL.revokeObjectURL` หลังคลิก
- ชื่อไฟล์ ASCII: `attendance-daily_2026-10-01_2026-10-31.csv`, `attendance-summary_2026-10-01_2026-10-31.csv` (+ `_{sid}` ถ้าเลือกคนเดียว)
- ส่งออก **ตามตัวกรองที่แสดงอยู่**; ถ้ามีวันยังไม่ยืนยันถามก่อน "มี N วันยังไม่ยืนยัน ส่งออกต่อหรือไม่"

### 6.2 การเขียนช่อง (REPORT CORE)
- `csvText(s)` สำหรับข้อความทั้งหมด (โดยเฉพาะที่มาจาก DB: ชื่อเล่น, ชื่อสาขา, sid, ป้าย): `s = String(s ?? '')`; ขึ้นต้นด้วย `=` `+` `-` `@` `\t` `\r` → เติม `'` ข้างหน้า; มี `,` `"` `\r` `\n` → ครอบ `"…"` และเปลี่ยน `"` เป็น `""`
- `csvNum(n, digits)` สำหรับตัวเลขที่ระบบคำนวณ: `null/undefined` → ช่องว่าง; ไม่ผ่าน guard (ตัวเลขติดลบที่ถูกต้องต้องยังเป็นตัวเลข); ทศนิยม `toFixed` ใช้จุด
- เวลา `HH:MM` จาก `hhmmOf(ts)` (Excel แปลงเป็นเวลาได้ ใช้คำนวณต่อได้)
- วันที่ ISO `YYYY-MM-DD` (Excel แปลงเป็นวันที่ตาม locale) + คอลัมน์วันในสัปดาห์จากตารางคงที่ `['อา.','จ.','อ.','พ.','พฤ.','ศ.','ส.']` (ไม่ใช้ Intl ใน core)
- ระยะเวลาไม่เขียนเป็น "8:15" (Excel ตีเป็นเวลาของวัน ยอดเกิน 24 ชม. เพี้ยน) ใช้นาทีเต็ม + ชั่วโมงทศนิยม 2 ตำแหน่ง

### 7.2 การโหลด (เร็ว + ประหยัด)
- ช่วง: วันนี้ย้อนหลังรวม 30 วัน (`i = 0..29`, `bkkDateOf(serverNow() − i·DAY_MS)`)
- `histLoad()`
  1. ถ้า cache ใน memory อายุ < 2 นาที และ `D.state.lastLogId` ไม่เปลี่ยน และไม่มี `D.corr[*].decidedAt` ใหม่กว่าเวลาโหลด → ใช้ของเดิม ไม่อ่าน
  2. ไม่อย่างนั้น แสดงจาก `localStorage['clock.hist.' + sid]` ทันที (ถ้ามี) พร้อม "กำลังอัปเดต..."
  3. `Promise.allSettled` ของ `get` 29 วัน (ข้ามวัน `timelineDate()` ที่ใช้ `D.logs`) — ส่งผ่าน WebSocket เดียวแบบ pipeline ปกติไม่ถึง 1 วินาทีบน 4G
  4. คำนวณ `dayReport` ต่อวัน เก็บเฉพาะผลสรุป (ไม่เก็บพิกัด) ลง memory + `localStorage` `{ v: 1, sid, savedAt, days: { d: { inTs, outTs, outPlus, breakMin, netMin, open, segCount, marks: [] } } }` (~3 KB)
  5. วันที่ get ล้มเหลว (ออฟไลน์) คงค่าจาก cache และแสดง "ไม่มีเน็ต — แสดงข้อมูลเมื่อ HH:MM"

- ล้าง cache เมื่อ `me.sid` เปลี่ยน/ถูกยกเลิกผูกเครื่อง (`onStaff` ส่วน `!me && prev`)

## 8. Security Rules

### 9.4 ตรวจใน Excel (เกณฑ์ตรวจรับ brief ข้อ 8)
1. Windows + Excel 2016 ขึ้นไป/Microsoft 365 (locale ไทย และอังกฤษถ้ามี): **ดับเบิลคลิก** ไฟล์ CSV (ไม่ใช้ Import)
2. ภาษาไทยในหัวตาราง ชื่อ สาขา หมายเหตุ อ่านได้ ไม่เป็น `à¸...`; แต่ละค่าอยู่คนละคอลัมน์
3. คอลัมน์ เข้า/ออก เป็นเวลา; วันที่เป็นวันที่ (locale ไทยอาจแสดง พ.ศ. ถือว่าปกติ)
4. CSV รายวัน: ใส่สูตรในคอลัมน์ว่าง R2 `=ROUND(((G2+H2)-F2)*1440-I2,0)` ลากลง → เท่ากับคอลัมน์ J "สุทธิ (นาที)" ทุกแถวที่มีเวลาออก (H = ออกวันถัดไป คิดเป็น 1 วัน)
5. `=SUMIF(C:C,"เอ",J:J)` ใน CSV รายวัน = "สุทธิ (นาที)" ของ เอ ใน CSV สรุป
6. Injection: ตั้งชื่อเล่นทดสอบ `=1+1`, `@SUM(1)`, `-2+3`, `เอ, "จูเนียร์"` → Excel แสดงเป็นข้อความตามตัวอักษร (3 ตัวแรกมี `'` นำหน้า) ไม่คำนวณ ไม่เลื่อนคอลัมน์
7. (เสริม) Google Sheets และ LibreOffice Calc (UTF-8, comma) ผลเหมือนกัน
8. บันทึกผลพร้อมรุ่น Excel/locale ในตาราง "ผ่าน" ของ testing.md

## 10. คำถามค้าง (ใช้ค่าเริ่มต้นไปก่อน เปลี่ยนภายหลังได้ที่ core + เทส)

1. **นาทีสายนับจากไหน** → *ค่าเริ่มต้น:* จากเวลาเข้ากะ (มา 08:12 = สาย 12 นาที) ไม่หักผ่อนผัน ตรงกับป้ายเดิม
2. **ขอบเขตสาย/พักเกินเป็นนาทีเต็ม** → *ค่าเริ่มต้น:* ใช่ (สายเมื่อเกินผ่อนผันอย่างน้อย 1 นาทีเต็ม; พักเกินเมื่อ ≥ limit + 1 นาที)
3. **วันทำงานนับวันที่ไม่มีเวลาออกด้วยไหม** → *ค่าเริ่มต้น:* นับ และแยกคอลัมน์ "ไม่มีเวลาออก"
4. **พักเกินคิดต่อวันหรือต่อครั้ง** → *ค่าเริ่มต้น:* ต่อวัน (พักรวมของวัน > breakLimitMin)
5. **รวมวันที่ยังไม่ยืนยันในรายงาน** → *ค่าเริ่มต้น:* รวม + แถบเตือน + ติ๊กกรองได้
6. **แยกชั่วโมงตามสาขา** → *ค่าเริ่มต้น:* ไม่แยก (ทั้งวันเป็นของสาขาของ in แรก)
7. **หน้าประวัติแสดงสาย/พักเกิน/ป้าย "เจ้าของยืนยันแล้ว"** → *ค่าเริ่มต้น:* ไม่แสดง (ป้ายยืนยันต้องเพิ่มกฎอ่าน `days/{d}/{sid}` = เปลี่ยน rules เป็นงานแยก R58)
8. **ใช้ shiftStart/breakLimitMin ปัจจุบันกับข้อมูลย้อนหลัง** → *ค่าเริ่มต้น:* ใช่ (เปลี่ยนเวลาเข้ากะแล้ว รายงานเดือนก่อนเปลี่ยนตาม)
9. **ช่วงรายงานสูงสุด** → *ค่าเริ่มต้น:* 92 วัน
10. **ทศนิยมชั่วโมงใน CSV** → *ค่าเริ่มต้น:* 2 ตำแหน่ง และมีคอลัมน์นาทีเต็มเสมอ
11. **เข้างานคนละช่วงกับกะ (สายหลายชั่วโมง)** → *ค่าเริ่มต้น:* นับตามสูตร เจ้าของตัดสินเอง
