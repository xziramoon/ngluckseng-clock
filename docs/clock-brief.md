## 1. สิ่งที่ต้องสร้าง

ข้อกำหนดรวม
- Single-file HTML (CSS/JS อยู่ในไฟล์เดียว) ตามแนวทางเดิมของร้าน ไม่ใช้ build tool
- Firebase Realtime Database โปรเจกต์เดิมของร้าน ใช้เฉพาะ node `attendance/` **ห้ามแตะ node อื่น** (มีข้อมูลสินค้า/STOCK MASTER อยู่)
- โฮสต์บน HTTPS (GitHub Pages หรือ Firebase Hosting) เพราะเบราว์เซอร์อ่าน GPS ได้เฉพาะ HTTPS
- Firebase config ใส่เป็นค่าคงที่ด้านบนไฟล์ (`FIREBASE_CONFIG = {...}`) ให้เจ้าของเติมเอง
- ใช้ Firebase JS SDK แบบ modular จาก CDN, แผนที่ใช้ Leaflet + OpenStreetMap (ไม่ต้องมี API key)

## 2. แอปมือถือ `clock.html` — ใช้ง่ายมาก่อนทุกอย่าง

### หลักการออกแบบ (ต้องทำตามทั้งหมด)
1. **หน้าจอหลักมีปุ่มใหญ่ปุ่มเดียว** เปลี่ยนตามสถานะ ไม่มีเมนูให้หลง
2. ปุ่มกินพื้นที่อย่างน้อยครึ่งจอ ตัวอักษรปุ่ม ≥ 28px ตัวอักษรทั่วไป ≥ 18px ใช้ได้ด้วยนิ้วโป้งมือเดียว
3. สีบอกความหมายชัด: เขียว = เข้างาน, ส้ม = เริ่มพัก, ฟ้า = กลับจากพัก, แดง = ออกงาน, เทา = กดไม่ได้
4. ทุกข้อความเป็นภาษาไทยพูดธรรมดา ไม่มีศัพท์เทคนิค (ไม่โชว์คำว่า GPS accuracy, error code)
5. บอกเหตุผลทุกครั้งที่กดไม่ได้ + บอกวิธีแก้ เช่น "อยู่ห่างร้าน 240 ม. — เดินเข้าใกล้ร้านอีกนิด"
6. ล็อกอินครั้งเดียวต่อเครื่อง ไม่ต้องใส่ PIN ทุกครั้ง (เครื่องผูกกับชื่อแล้ว)
7. หลังกดสำเร็จ: สั่นมือถือ + เครื่องหมายถูกตัวใหญ่ + แสดงเวลาที่บันทึก 2 วินาที
8. ไม่มีโหมดมืด ไม่มีอนิเมชันเกินจำเป็น โหลดหน้าแรก < 2 วินาที

### หน้าจอ
**A. ลงทะเบียน (ครั้งแรกเท่านั้น)**
- รายชื่อพนักงานเป็นปุ่มใหญ่ (ชื่อเล่น) → แตะชื่อตัวเอง → ใส่ PIN 4 หลักด้วยแป้นตัวเลขขนาดใหญ่ที่สร้างเอง
- ส่งคำขอผูกเครื่อง → แสดง "รอเจ้าของอนุมัติ" และอัปเดตเองแบบ realtime เมื่ออนุมัติ
- ขอสิทธิ์ตำแหน่งพร้อมคำอธิบายสั้น: "ร้านใช้ตำแหน่งเฉพาะตอนกดปุ่ม เพื่อยืนยันว่าอยู่ที่ร้าน"

**B. หน้าหลัก (เกือบทั้งหมดของการใช้งาน)**
```
┌─────────────────────────────┐
│ สวัสดี น้องเอ   สาขาวงเวียน  │
│ ● อยู่ในร้าน (ห่าง 12 ม.)     │  ← แถบสถานะ เขียว/แดง อัปเดตทุก 5 วิ ขณะเปิดหน้า
│                             │
│   ┌───────────────────┐     │
│   │                   │     │
│   │    เข้างาน         │     │  ← ปุ่มใหญ่ปุ่มเดียว
│   │                   │     │
│   └───────────────────┘     │
│                             │
│ วันนี้: เข้า 08:02            │  ← ไทม์ไลน์ของวันนี้ บรรทัดสั้น
│                             │
│ [ประวัติ]      [แจ้งแก้เวลา] │  ← ลิงก์เล็กด้านล่าง
└─────────────────────────────┘
```
- สถานะ "พักอยู่": ปุ่มใหญ่ = "กลับจากพัก" + นาฬิกานับเวลาพักตัวใหญ่ เกินกำหนดเปลี่ยนเป็นสีส้ม
- สถานะ "กำลังทำงาน": ปุ่มใหญ่ = "เริ่มพัก" และปุ่มรองขนาดกลาง = "ออกงาน" (ต้องกดยืนยันอีกครั้ง กันกดพลาด)
- สถานะ "ออกงานแล้ว": แสดงสรุปวันนี้ (ทำงานกี่ชม. พักกี่นาที) ปุ่มเทา
- เลือกสาขาอัตโนมัติจากสาขาที่ใกล้ที่สุด ไม่ต้องให้พนักงานเลือก

**C. ประวัติ** — 30 วันล่าสุดของตัวเอง แบบรายการวัน: เข้า / พักรวม / ออก / ชม.สุทธิ

**D. แจ้งแก้เวลา** — เลือกวัน, เลือกประเภท (ลืมกดเข้า/ออก/พัก), ใส่เวลา, เหตุผล (ปุ่มเหตุผลสำเร็จรูป + พิมพ์เองได้) → ส่งไปให้ master อนุมัติ

### สถานะและลำดับการกด
`off → (in) → working ⇄ (break_start / break_end) ⇄ on_break ; working → (out) → done`
- พักได้หลายรอบ, ออกงานระหว่างพักไม่ได้, กดซ้ำภายใน 30 วินาทีถูกบล็อก (กันกดเบิ้ล)
- ข้ามเที่ยงคืน: ผูก log กับ "วันทำงาน" ที่เริ่มตอนกดเข้างาน

## 3. การตรวจตำแหน่ง (Geofence)

ค่าต่อสาขาเก็บใน `attendance/branches/{branchId}` แก้จาก master ได้
| ค่า | ค่าเริ่มต้น |
| --- | --- |
| `radius` (ม.) | 80 (ปรับได้ 30–300) |
| `maxAccuracy` (ม.) | 60 |
| `graceFactor` | 1.5 |
| `breakLimitMin` | 60 |

ขั้นตอนตอนกดปุ่ม
1. `getCurrentPosition({enableHighAccuracy:true, timeout:10000, maximumAge:0})` อ่าน 3 ครั้งภายใน ~5 วิ เลือกค่าที่ `accuracy` ดีที่สุด (แสดง "กำลังหาตำแหน่ง..." ระหว่างนั้น)
2. ระยะ = Haversine(ตำแหน่ง, ร้านที่ใกล้สุด)
3. ผล:
   - `distance ≤ radius` และ `accuracy ≤ maxAccuracy` → บันทึก `flag: null`
   - `distance ≤ radius × graceFactor` หรือ accuracy แย่กว่าเกณฑ์แต่ไม่เกิน 2 เท่า → บันทึกได้ `flag: "borderline"`
   - นอกนั้น → ไม่บันทึก แสดงระยะห่างและคำแนะนำ
4. ธงสงสัยอัตโนมัติ `flag: "suspect"`: accuracy เป็น 0 หรือ < 3 ม., พิกัดซ้ำเดิมทศนิยม 6 ตำแหน่งกับครั้งก่อน, กดต่างสาขาห่างกัน < 10 นาที
5. ไม่ติดตามตำแหน่งเบื้องหลัง อ่านเฉพาะตอนเปิดหน้าหลัก (แถบสถานะ) และตอนกดปุ่ม

## 4. ตัว Master `clock-master.html` (PC, ต้องมีรหัสผ่าน)

### การเข้าใช้
- ล็อกอินด้วย **Firebase Authentication แบบ Email/Password** (บัญชีแอดมินสร้างใน Firebase Console)
- **ห้ามเก็บรหัสผ่านไว้ในโค้ด HTML** — สิทธิ์แอดมินตรวจที่ Security Rules ผ่าน `attendance/admins/{uid}: true`
- ล็อกเอาต์อัตโนมัติเมื่อไม่ใช้งาน 30 นาที, มีปุ่มล็อกหน้าจอ
- ทุกการแก้ไขบันทึก `editedBy`, `editedAt`, ค่าเดิม ลง `attendance/audit/`

### หน้าจอ (แท็บด้านซ้าย)
1. **สถานะวันนี้** — การ์ดพนักงานแยกสาขา: ยังไม่มา / ทำงาน / พักอยู่ (นับเวลา) / ออกแล้ว; มาสายแสดงสีส้ม; realtime
2. **รอตรวจ** (มีตัวเลขแจ้งเตือนบนแท็บ) รวม 3 อย่างในหน้าเดียว แต่ละรายการมีปุ่ม ✔ ยืนยัน / ✘ ไม่ยืนยัน / ✎ แก้:
   - log ที่ติดธง borderline/suspect (แสดงจุดบนแผนที่เทียบวงรัศมี)
   - คำขอแก้เวลาจากพนักงาน
   - คำขอผูกเครื่องใหม่
3. **บันทึกเวลา** — ตารางเลือกวัน/ช่วงวัน/พนักงาน/สาขา, แก้เวลาในช่องได้, เพิ่ม log แทนพนักงานได้ (ติดป้าย "แอดมินบันทึก"), ยืนยันทั้งวันได้ (`confirmed: true` = ล็อกไม่ให้แก้ต่อ เว้นแต่ปลดล็อก)
4. **รายงาน** — รายวัน/รายเดือนต่อคน: ชม.ทำงานสุทธิ, พักรวม, มาสาย (นาที/ครั้ง), พักเกิน (ครั้ง), จำนวนวันทำงาน; ส่งออก CSV (UTF-8 BOM ให้ Excel อ่านไทยได้)
5. **พนักงาน** — เพิ่ม/ปิดบัญชี, ชื่อเล่น, สาขาหลัก, เวลาเข้ากะ, รีเซ็ต PIN, ยกเลิกผูกเครื่อง
6. **ตั้งค่าสาขา** — แผนที่ Leaflet: หมุดลากได้, วงกลมรัศมีปรับด้วยสไลเดอร์แสดงผลทันที, ช่อง lat/lng, ปุ่ม "ใช้ตำแหน่งเครื่องนี้", ค่า maxAccuracy/breakLimitMin; เริ่มต้น 2 สาขา: `wongwian` (สาขาวงเวียน), `klongyang` (สาขาแยกคลองยาง)

## 5. โครงสร้างข้อมูล (`attendance/`)

```
attendance/
  admins/{uid}: true
  branches/{branchId}: { name, lat, lng, radius, maxAccuracy, graceFactor, breakLimitMin }
  staff/{staffId}: { nickname, pinHash, branchId, shiftStart:"08:00", active, uid, deviceApproved }
  deviceRequests/{uid}: { staffId, requestedAt(server), userAgent }
  state/{staffId}: { status, workDate, since(server) }
  logs/{workDate YYYY-MM-DD}/{staffId}/{pushId}:
      { type:"in"|"break_start"|"break_end"|"out", ts(server), lat, lng, accuracy,
        distance, branchId, uid, flag:null|"borderline"|"suspect",
        source:"app"|"admin", review:null|"approved"|"rejected" }
  days/{workDate}/{staffId}: { confirmed, confirmedBy, confirmedAt }
  corrections/{pushId}: { staffId, workDate, type, time, reason, status:"pending"|"approved"|"rejected", decidedBy, decidedAt }
  audit/{pushId}: { path, before, after, by, at(server) }
```
- เวลาใช้ `serverTimestamp()` เสมอ ห้ามใช้นาฬิกาเครื่อง (แสดงผลเป็นเวลาไทย Asia/Bangkok)
- พนักงานใช้ **Anonymous Auth** → `uid` ของเครื่องนั้นคือการผูกเครื่องโดยธรรมชาติ; อนุมัติแล้ว master เขียน `staff/{id}/uid = uid`
- `pinHash` = SHA-256(staffId + PIN) ใช้ตอนลงทะเบียน/ผูกเครื่องใหม่เท่านั้น

## 6. Security Rules (หลักที่ต้องมี)
- `admins`: อ่าน/เขียนได้เฉพาะแอดมิน (สร้างรายการแรกเองใน Console)
- `branches`, `staff`: ทุกคนที่ล็อกอินอ่านได้ (ยกเว้น `pinHash` อ่านได้เฉพาะแอดมิน — แยกเก็บที่ `staffSecret/` ถ้าจำเป็น), เขียนได้เฉพาะแอดมิน
- `logs/{d}/{staffId}/{id}`: พนักงานเขียนได้เมื่อ `staff/{staffId}/uid === auth.uid`, **สร้างใหม่เท่านั้น** (`!data.exists()`), `ts === now`, `source === "app"`; แก้/ลบได้เฉพาะแอดมิน
- `state/{staffId}`: เขียนได้โดยเจ้าของ uid หรือแอดมิน
- `corrections`: พนักงานสร้างของตัวเองได้ สถานะ `pending` เท่านั้น; เปลี่ยนสถานะได้เฉพาะแอดมิน
- `days`, `audit`: แอดมินเท่านั้น
- ส่งไฟล์ `database.rules.json` แบบรวมเข้ากับ rules เดิมได้ (ให้ rules ของ node อื่นคงเดิม)

## 7. ลำดับการสร้าง
1. **เฟส 1 (MVP)**: `clock.html` ครบ หน้า A–B + geofence + สถานะ + เวลาเซิร์ฟเวอร์; `clock-master.html` ล็อกอิน + สถานะวันนี้ + ตั้งค่าสาขา + พนักงาน + อนุมัติเครื่อง; rules
2. **เฟส 2**: ธงสงสัย, หน้ารอตรวจ, คำขอแก้เวลา (หน้า D), บันทึกเวลาแก้ไข/ยืนยัน, audit
3. **เฟส 3**: รายงาน + ส่งออก CSV, ประวัติฝั่งพนักงาน (หน้า C)
4. **ภายหลัง (ยังไม่ต้องทำ)**: เซลฟี่ตอนกด, QR หมุนบนจอ PC, แจ้งเตือน LINE ผ่าน Messaging API + Cloud Function

## 9. ค่าที่ยังต้องให้เจ้าของยืนยัน (ใช้ค่าเริ่มต้นไปก่อน แก้ได้ใน master)
