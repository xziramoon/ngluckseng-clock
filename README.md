## ขั้นที่ 0 ตรวจกฎ Firebase เดิมก่อน (สำคัญมาก ทำก่อนเปิดให้พนักงานสมัคร)

ระบบนี้ให้พนักงานสมัครบัญชีเองด้วยชื่อผู้ใช้และรหัสผ่าน จึงต้องเปิด Email/Password และการสมัคร (sign-up) ไว้ ผลคือ **ใครก็ได้บนอินเทอร์เน็ตสร้างบัญชีในโปรเจกต์นี้ได้** ถ้ากฎของข้อมูลเดิม (เช่น STOCK MASTER) ใช้ `auth != null` หรือ `auth.token.firebase.sign_in_provider !== 'anonymous'` หรือเช็กโดเมนอีเมล คนแปลกหน้าจะอ่าน/เขียนข้อมูลเดิมได้ทันที

1. Firebase Console > Realtime Database > Rules > คัดลอกกฎเดิมทั้งหมดเก็บสำรองไว้ก่อน
2. ดูที่ระดับบนสุดของ `"rules"` ถ้ามี `".read"` หรือ `".write"` อยู่ตรงนั้น (เช่น `true` หรือ `"auth != null"`) กฎของ attendance จะไม่มีผล เพราะสิทธิ์ของ RTDB ไหลลงไปยังลูกทั้งหมดและเพิกถอนที่ชั้นล่างไม่ได้ ต้องย้ายสิทธิ์นั้นลงไปไว้ที่ node ของข้อมูลเดิมแต่ละตัวก่อน
3. ทุก node ของข้อมูลเดิมที่ใช้ `auth != null` (หรือ `sign_in_provider !== 'anonymous'`) ให้เปลี่ยนเป็น allowlist:
   `"auth != null && root.child('shopUsers/' + auth.uid).val() === true"`
   แล้วเพิ่ม uid ของ **ทุกบัญชี** ที่โปรแกรมเดิมใช้ล็อกอิน (เช่น บัญชีของ STOCK MASTER/POS ทุกเครื่อง ทุกคน) ลงใน `shopUsers/<UID>` = `true` (boolean) ทาง Console > Data **ถ้าตกหล่นบัญชีใด บัญชีนั้นจะเข้าข้อมูลเดิมไม่ได้ทันทีที่เผยแพร่กฎ** ควรเพิ่ม `shopUsers` ให้ครบก่อนแล้วค่อยเผยแพร่กฎ ส่วน `shopUsers` ให้ตั้งกฎ `".read": false, ".write": false` (Console เขียนได้เสมอเพราะไม่ผ่านกฎ)
4. ถ้าข้อมูลเดิมเปิดแบบ `true` (ไม่ต้องล็อกอิน) อยู่แล้ว ระบบนี้ไม่ได้ทำให้แย่ลง แต่ควรแก้แยกต่างหาก
5. ปิดวิธีล็อกอิน **Anonymous** (ระบบนี้ไม่ใช้แล้ว) **แต่ต้องตรวจก่อนว่า STOCK MASTER/POS หรือโปรแกรมอื่นของร้านล็อกอินแบบ Anonymous อยู่หรือไม่** ถ้ามี การปิดจะทำให้โปรแกรมนั้นเข้าไม่ได้ ให้เปลี่ยนวิธีล็อกอินของโปรแกรมนั้นหรือเว้นไว้ก่อน (ระบบลงเวลานี้ไม่ต้องใช้ Anonymous)
6. ห้ามแตะอย่างอื่นนอกจากกฎของ node ที่ระบุในข้อ 3 รวมกับ `attendance` และ `shopUsers`
7. ทดสอบใน Rules Playground: ผู้ใช้ provider `password` uid ใหม่ที่ไม่อยู่ใน `shopUsers` ต้องอ่าน/เขียน node เดิมไม่ได้

## ติดตั้ง

1. **เปิดวิธีล็อกอิน** Firebase Console > Authentication > Sign-in method > เปิด **Email/Password** (ไม่ต้องเปิด Anonymous) และตรวจว่า Authentication > Settings > User actions เปิด "Enable create (sign-up)" ไว้ พนักงานล็อกอินด้วยชื่อผู้ใช้ ระบบสร้างอีเมลสมมติ `<ชื่อผู้ใช้>@staff.ngluckseng.invalid` ให้เอง (ไม่ต้องมีอีเมลจริง และไม่มีการส่งอีเมลใดๆ) **ข้อควรตรวจ: ทดสอบกับ Auth emulator แล้วเท่านั้น ยังไม่เคยลองกับ Firebase จริง** หลังติดตั้งให้ลองสมัครบัญชีทดสอบ 1 บัญชีจริงก่อน ถ้า Firebase ปฏิเสธโดเมน `.invalid` (ข้อความ invalid-email) ต้องเปลี่ยนค่าคงที่โดเมนใน `clock.html`/`clock-master.html` (ดู docs/plan-auth-v2.md)
2. **โดเมนที่อนุญาต** Authentication > Settings > Authorized domains > เพิ่ม `xziramoon.github.io` (`localhost` มีอยู่แล้วตามปกติ)
3. **สร้างแอดมินคนแรก** Authentication > Users > Add user (อีเมลจริงของเจ้าของ + รหัสผ่าน ห้ามใช้โดเมน `@staff.ngluckseng.invalid` เพราะระบบถือเป็นบัญชีพนักงานและไม่ให้สิทธิ์แอดมิน) > คัดลอก **User UID** > Realtime Database > Data > เพิ่ม `attendance/admins/<UID>` = `true` (ชนิด boolean ไม่ใช่ข้อความ) การเขียนใน Console ไม่ผ่านกฎ จึงเพิ่มได้
4. **รวมกฎ** เปิดไฟล์ `database.rules.json` เอาก้อน `"attendance": { ... }` ไปวางเป็นพี่น้อง (sibling) กับ node เดิมใน `"rules"` **ห้ามวางทับทั้งหน้า** แล้วให้ Boss ตรวจก่อนกด Publish
5. **เอา config** Project settings > Your apps > Web app (ถ้ายังไม่มีให้สร้าง) > คัดลอกค่าไปใส่ `FIREBASE_CONFIG` ที่ด้านบนของ **ทั้งสองไฟล์** (`clock.html` และ `clock-master.html`) ต้องมี `databaseURL` ของภูมิภาค เช่น `https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app`
   config ของเว็บไม่ใช่ความลับ สิ่งที่กันข้อมูลคือกฎ (rules) ในข้อ 4
6. **GitHub Pages** Settings > Pages > Deploy from branch `main` / `(root)`
7. (แนะนำ) Google Cloud Console > APIs & Services > Credentials > จำกัด API key ให้ใช้ได้เฉพาะ HTTP referrer `https://xziramoon.github.io/*` และ `http://localhost:*/*`

repo นี้เป็น public อย่าคอมมิตข้อมูลลับอื่นใด (ค่า config เว็บของ Firebase ไม่ถือเป็นความลับ แต่รหัสผ่านแอดมิน/service account ห้ามใส่เด็ดขาด)

## เริ่มใช้งาน

1. เปิด `clock-master.html` > ล็อกอินด้วยบัญชีแอดมิน
2. แท็บ **ตั้งค่าสาขา** > กด "สร้าง 2 สาขาเริ่มต้น" > ไปยืนที่ร้าน เปิดหน้านี้จากมือถือ กด "ใช้ตำแหน่งเครื่องนี้" แล้วบันทึก (หรือวาง "13.xxxx, 100.xxxx" จาก Google Maps) ปรับรัศมีด้วยสไลเดอร์ ค่าใหม่มีผลกับมือถือพนักงานทันที ไม่ต้องรีเฟรช
   - สาขาวงเวียนมีพิกัดหน้าร้านใส่มาให้แล้ว (17.318062, 99.832187 — 59/9 ถ.เทศบาลดำริ 3 สวรรคโลก วัดจาก GPS หน้าร้านจริง; ค่าเริ่มต้นรัศมี 10 ม. ยอมรับสัญญาณ ±30 ม. ชายขอบ x2 = 20 ม.) ตรวจบนภาพดาวเทียมอีกครั้งแล้วกดบันทึกได้เลย ส่วนสาขาแยกคลองยางยังต้องปักเอง
3. พนักงานสมัครเอง: เปิด `clock.html` ที่มือถือ > แท็บ "สมัครใช้งาน" > ตั้งชื่อผู้ใช้ (a-z 0-9 และ _ ยาว 3-20 ตัว) ชื่อเล่น รหัสผ่าน (อย่างน้อย 6 ตัว ตัวเลขล้วนได้) > ระบบผูกมือถือเครื่องนั้นกับคำขอ (ขอสิทธิ์ตำแหน่งตอนนี้เลย) > รอ
4. แท็บ **รอตรวจ** > การ์ด "สมัครใช้งาน" > เลือกสาขา/เวลาเข้ากะ (ปรับได้) แล้วกดอนุมัติ มือถือพนักงานจะเข้าหน้าหลักเอง ปิดรับสมัครได้ที่สวิตช์ "เปิดรับสมัครพนักงานใหม่ในแอป" ในแท็บ ตั้งค่าสาขา (เปิดอยู่เป็นค่าเริ่มต้น แนะนำให้ปิดเมื่อพนักงานสมัครครบแล้ว)
5. หรือเจ้าของสร้างบัญชีให้เอง: แท็บ **พนักงาน** > เพิ่มชื่อผู้ใช้ ชื่อเล่น สาขา เวลาเข้ากะ และรหัสผ่านเริ่มต้น (พนักงานล็อกอินแล้วขอใช้เครื่องของตนเอง เจ้าของอนุมัติในแท็บ รอตรวจ)
6. **ลืมรหัสผ่าน** ไม่มีการเปลี่ยนรหัสผ่านในแอป ให้พนักงานเลือก "ลืมรหัสผ่าน" > ตั้งรหัสใหม่ > เจ้าของอนุมัติการ์ด "ลืมรหัสผ่าน" (ใช้ข้อมูลเวลาเดิมต่อ) หรือเจ้าของกด "ตั้งบัญชีใหม่ (ลืมรหัส)" ที่แถวพนักงาน
7. **เปลี่ยนมือถือ** ล็อกอินบนเครื่องใหม่ > "ขอใช้เครื่องนี้" > เจ้าของอนุมัติ เครื่องเก่าใช้ลงเวลาไม่ได้อีก ถ้าพนักงานเห็นแถบเตือน "มีคนขอใช้บัญชีของคุณบนมือถือเครื่องอื่น" และไม่ใช่ตัวเอง ให้แจ้งเจ้าของ

## แก้ไขเวลาและการยืนยันวัน

ทั้งหมดอยู่ใน `clock-master.html` ทุกการแก้บันทึกประวัติ (ใคร แก้อะไร เมื่อไร เหตุผล) ไว้ใน `audit` และ rules บังคับให้ต้องมีประวัติทุกครั้งที่แก้ log/สถานะ/ยืนยันวัน แอดมินลบ log ไม่ได้ ใช้ "ยกเลิกรายการ" แทน (เก็บหลักฐานไว้)

- **รอตรวจ** รวมรายการที่ต้องตรวจ: log ติดธง (ใกล้ขอบเขต/น่าสงสัย), วันทำงานไม่ตรงเวลาจริง, กะยาวเกิน 16 ชม., ลืมออกงาน, สถานะผิดปกติ คลิกการ์ดเพื่อดูตำแหน่งบนแผนที่ (วงเขียว = รัศมี, วงส้ม = ชายขอบ, วงฟ้า = ความแม่นยำ) ปุ่ม ✔ ยืนยัน / ✘ ไม่ยืนยัน / ✎ แก้ **✘ ไม่ยืนยัน = ไม่นับเวลานั้นเลย** (เหมือนยกเลิก) และถ้าทำให้ลำดับเสียระบบจะถามว่าจะไม่ยืนยันทั้งกะหรือไม่
- **คำขอแก้เวลา** พนักงานกด "แจ้งแก้เวลา" ในแอป (ย้อนหลังได้ตามค่า `correctionDays` ค่าเริ่มต้น 7 วัน) เจ้าของกด ✔ ใช้ตามที่ขอ, ✎ แก้เวลาก่อนอนุมัติ หรือ ✘ ไม่ยืนยันพร้อมข้อความ ผลขึ้นในแอปพนักงานพร้อมจุดแดง
- **บันทึกเวลา** ตารางต่อคนต่อวัน (วันเดียวหรือช่วงไม่เกิน 31 วัน) ดับเบิลคลิกช่อง เข้า/ออก เพื่อแก้เร็ว ปุ่ม "แก้" เปิดตัวแก้ไขทั้งวัน (เพิ่ม/ยกเลิก/กู้คืนรายการ เวลาหลังเที่ยงคืนติ๊ก +1 วัน) ระบบตรวจลำดับเหตุการณ์และปรับสถานะของพนักงานให้ตรงกับบันทึกที่แก้ เวลาจริงจากเซิร์ฟเวอร์ของ log ที่มาจากมือถือเก็บไว้ถาวรใน `origTs` ส่วนพิกัด/ระยะแก้ไม่ได้
- **ยืนยันวัน** ล็อกวันนั้นไม่ให้แก้ต่อ (ทั้งเจ้าของและพนักงาน) จนกว่าจะกด "ปลดล็อก" ยืนยันได้เมื่อกะปิดแล้วเท่านั้น
- **ปฏิทินวันทำงาน** (แท็บ ตั้งค่าสาขา) สร้างปฏิทิน 5 ปีแล้วเปิด "บังคับใช้" เพื่อให้ rules ปฏิเสธการกดเข้างานที่เลือกวันทำงานไม่ตรงวันจริง **ปิดไว้เป็นค่าเริ่มต้น** เปิดเมื่อใช้งานจริงแล้วราบรื่น และอย่าให้ปฏิทินหมดอายุ (ถ้าเหลือน้อยกว่า 60 วันจะมีแถบเตือนแดง ถ้าหมดขณะเปิดบังคับ พนักงานทุกคนกดเข้างานไม่ได้ ปิดสวิตช์ได้ทันที)
- ค่าที่ตั้งได้ในแท็บ ตั้งค่าสาขา > ค่าทั่วไป: `reviewDays` (คิวรอตรวจมองย้อนหลังกี่วัน 7-92 ค่าเริ่มต้น 31) และ `correctionDays` (พนักงานขอแก้ย้อนหลังได้กี่วัน 1-62 ค่าเริ่มต้น 7)

- ข้อจำกัด: ถ้าเปิดผ่าน http (ไม่ใช่ https/localhost) GPS จริงใช้ไม่ได้ (ใช้โหมดจำลองได้) แผนที่ในหน้าเจ้าของโหลดจากอินเทอร์เน็ต; ไม่ต้องเพิ่ม CACHE_VERSION ใน sw.js

## รายงานและ CSV

แท็บ **รายงาน** ใน `clock-master.html` (อ่านอย่างเดียว คลิกแถวเพื่อไปแก้ในแท็บ บันทึกเวลา)
- **เวลาเข้า/เลิกกะ**: แท็บ พนักงาน ตั้ง "เวลาเข้ากะ" (ค่าเริ่มต้นพนักงานใหม่ 07:00) และ "เวลาเลิกกะ" (ค่าเริ่มต้น 18:00 พนักงานเดิมที่ไม่มีค่านี้ถือเป็น 18:00) ถ้าเวลาเลิกกะน้อยกว่าเวลาเข้ากะ ถือว่าเป็นกะข้ามคืน (เลิกวันถัดไป)
- **สูตร** (นับเป็นนาทีเต็มตามเวลาที่แสดง ตัดวินาที): ชั่วโมงสุทธิ = ออก - เข้า - พักรวม เฉพาะกะที่มีเวลาออก; **มาสาย** = เข้าแรกของวัน หลังเวลาเข้ากะเกินผ่อนผัน (ค่าทั่วไป lateGraceMin) นาทีสายนับจากเวลาเข้ากะเต็มจำนวน; **พักเกิน** = พักรวมของวัน มากกว่าเวลาพักของสาขา (นับ 1 ครั้งต่อวัน + นาทีที่เกิน); **ออกก่อนเวลา** = เวลาออกสุดท้ายก่อนเวลาเลิกกะ (นับเป็นครั้ง + นาที เฉพาะวันที่มีเวลาออกครบ); กะข้ามคืนนับในวันที่เริ่มกะ; กะที่ยังไม่ปิดไม่นับชั่วโมง (แสดง "กำลังทำงาน" หรือ "ไม่มีเวลาออก")
- **วันที่ยังไม่ยืนยัน** รวมในรายงานโดยค่าเริ่มต้น มีแถบเตือนและติ๊ก "เฉพาะวันที่ยืนยันแล้ว"; ค่าเข้ากะ/เลิกกะ/เวลาพัก/ผ่อนผันใช้ค่าปัจจุบันกับทุกวันในอดีต
- **CSV** 2 ไฟล์: รายวัน (1 แถวต่อกะ) และสรุปตามคน (มีแถว "รวม") ตามตัวกรองที่แสดง; UTF-8 มี BOM, ขึ้นบรรทัดด้วย CRLF, คั่นด้วยจุลภาค, ไม่มีบรรทัด `sep=` (ทำให้ Excel ไทยเพี้ยน), ระยะเวลาเป็นนาทีเต็ม + ชั่วโมงทศนิยม 2 ตำแหน่ง (ไม่เขียนเป็น 8:15), ข้อความจากฐานข้อมูล (ชื่อ สาขา ป้าย) ที่ขึ้นต้นด้วย `= + - @` ถูกเติม `'` นำหน้ากัน CSV injection; **คอลัมน์ "รหัสพนักงาน" เขียนเป็น `id:` ตามด้วยรหัส เช่น `id:-OAa1`** เหตุผล: รหัสของ Firebase ขึ้นต้นด้วย `-` ซึ่ง Excel ตีเป็นสูตรแล้วขึ้น #NAME? ส่วน `'` นำหน้าจะเห็นเป็นตัวอักษรเกินในไฟล์ CSV และ `="-OAa1"` ก็เป็นสูตรเอง คำนำหน้า `id:` ทำให้เป็นข้อความธรรมดาที่ไม่ใช่สูตร และใช้ join/VLOOKUP ข้ามไฟล์รายวัน-สรุปได้ (ทั้งสองไฟล์ใช้รูปแบบเดียวกัน) เปิดด้วยการดับเบิลคลิกใน Excel ได้เลย (ร้านใช้ Windows ภาษาไทย ตัวคั่นจุลภาค ถ้าเครื่องใช้ตัวคั่น `;` ให้ใช้ Data > From Text/CSV เลือก UTF-8 และ comma)
- ช่วงที่เก่ากว่าหน้าต่าง reviewDays ระบบอ่านจากฐานข้อมูลแบบ range query ครั้งเดียว (logs + days อย่างละ 1 query ราว 0.5 MB ต่อเดือน) แล้วจำไว้ใน session; ปุ่ม "โหลดใหม่" อ่านใหม่
- ข้อจำกัด: ไม่แยกชั่วโมงตามสาขา (ทั้งวันนับเป็นสาขาของการเข้างานแรก) เวลาเข้ากะที่เปลี่ยนจะมีผลย้อนหลังกับรายงานเดือนก่อน ไม่คิดค่าแรง/OT
- **พักรวม** ในรายงาน/CSV นับเฉพาะกะที่ปิดแล้ว (กะที่ไม่มีเวลาออกหรือกำลังทำงานเว้นช่องพักรวมในไฟล์รายวัน และแสดง "—" บนจอ) ผลรวมคอลัมน์พักรวมของไฟล์รายวันจึงเท่ากับยอดในไฟล์สรุปเสมอ ส่วน **พักเกิน** เทียบพักทุกกะของวัน (รวมกะที่ยังไม่ปิด) เพื่อให้เห็นการพักเกินแม้ลืมกดออก
- **ออกก่อนเวลา**: ถ้าพนักงานยังไม่มี shiftEnd จะใช้ 18:00 เฉพาะคนที่เข้ากะก่อน 18:00 (กะเย็น/ดึกที่ยังไม่ตั้งเวลาเลิกกะ ไม่คิดออกก่อนเวลา) การแก้พนักงานไม่เขียน shiftEnd ให้เองถ้าเจ้าของไม่ได้กรอก
- **out ซ้ำ** ในกะที่ปิดแล้ว (เช่น เข้า 07:00 ออก 12:00 แล้ว in ที่สองถูกยกเลิก แต่ออก 17:00 ยังอยู่) ระบบไม่ขยายกะเดิม ไม่นับ out ที่เกิน และขึ้นป้าย "out ซ้ำ (ไม่นับ)" ในบันทึกเวลา/รายงาน ให้แก้ในแท็บ บันทึกเวลา
- ตัวเลขชั่วโมงนับเป็นนาทีเต็มทุกหน้าจอ (บันทึกเวลา สถานะวันนี้ แอปพนักงาน รายงาน) จึงอาจต่างจากเวอร์ชันเดิมไม่เกิน 1 นาที

หน้า **ประวัติ** ในแอปพนักงาน (ปุ่ม "ประวัติ" ใต้ไทม์ไลน์): 30 วันล่าสุด เข้า/ออก/พักรวม/ชั่วโมงสุทธิ + ป้ายคำขอแก้เวลา (ไม่แสดงสาย/พักเกิน) อ่านข้อมูลวันละ 1 get (29 get ต่อการเปิดครั้งแรก) จำไว้ในเครื่อง เปิดซ้ำภายใน 2 นาทีไม่อ่านใหม่ และแสดงจากที่จำไว้ทันทีเมื่อไม่มีเน็ต

## แก้ปัญหาที่พบบ่อย

- **ตำแหน่งถูกปฏิเสธ** iPhone: การตั้งค่า > ความเป็นส่วนตัวฯ > บริการหาตำแหน่งที่ตั้ง > Safari/เว็บไซต์ > ขณะใช้งานแอป / Android: แตะรูปแม่กุญแจข้างลิงก์ > สิทธิ์ > ตำแหน่ง > อนุญาต
- **iPhone แจ้ง "ตำแหน่งที่แม่นยำ" ปิดอยู่** เปิด "ตำแหน่งที่แม่นยำ" ในการตั้งค่าตำแหน่งของเว็บนั้น
- **เปลี่ยนมือถือ/ล้างข้อมูลเบราว์เซอร์** กุญแจเครื่องหาย ต้องล็อกอินแล้วกด "ขอใช้เครื่องนี้" รอเจ้าของอนุมัติ เครื่องเก่าจะใช้ไม่ได้หลังอนุมัติเครื่องใหม่
- **ลืมรหัสผ่าน / ล็อกอินไม่ได้** ดูข้อ 6 ของหัวข้อ เริ่มใช้งาน (ไม่มีเปลี่ยนรหัสผ่านในแอปและไม่มีรีเซ็ตทางอีเมล)
- **พนักงานลืมกดออกงาน** ผ่านไป 16 ชั่วโมงแล้วระบบให้กดเข้างานใหม่ได้ (เจ้าของเห็นป้าย "ลืมออกงาน" ในหน้าสถานะและในคิวรอตรวจ พนักงานกด "แจ้งเวลาออกของกะก่อน" ได้ เจ้าของแก้ย้อนหลังในแท็บ บันทึกเวลา)
- **ทำงานได้กะเดียวต่อวัน** หลังออกงานแล้วเข้าใหม่ในวันเดียวกันไม่ได้

## ข้อจำกัดที่ควรรู้

- **ตำแหน่งปลอมได้**: กฎตรวจไม่ได้ว่าพิกัดเป็นของจริง แอปปลอมตำแหน่ง (mock location) หรือสคริปต์ที่ยิงตรงเข้าฐานข้อมูลอาจผ่านได้ กฎบังคับได้แค่ชนิดข้อมูล ช่วงค่า เวลาเซิร์ฟเวอร์ และระยะที่อ้างต้องไม่เกินรัศมี x ตัวคูณชายขอบของสาขา ส่วนที่เหลือพึ่งธง "น่าสงสัย" กับการตรวจของเจ้าของ
- **วันทำงานเลือกเองได้ (ข้อจำกัดที่ทราบ)**: กฎของ Firebase แปลงเวลาปัจจุบันเป็น "วันที่" ไม่ได้ พนักงานที่แก้โค้ดเองอาจเลือกวันทำงานย้อนหลังหรือล่วงหน้าตอนกดเข้างานเพื่อเลี่ยงกติกา "กะเดียวต่อวัน" ได้ เวลาจริงของ log (ts) ยังเป็นเวลาเซิร์ฟเวอร์เสมอ master จับกรณีนี้ได้สองทาง (1) คิวรอตรวจขึ้นการ์ด "วันไม่ตรง" และ "สถานะผิดปกติ" พร้อมปุ่ม "ย้ายไปวันที่ถูกต้อง" และหน้าสถานะวันนี้ขึ้นป้ายแดง (2) เปิด "บังคับใช้ปฏิทิน" เพื่อให้ rules ปฏิเสธตั้งแต่ตอนเขียน (ปิดไว้เป็นค่าเริ่มต้น ดูหัวข้อ แก้ไขเวลาและการยืนยันวัน และเทส R23/R45)
- **audit ของพนักงาน/สาขา** บันทึกแบบ best-effort ฝั่ง master (ไม่ได้บังคับใน rules) ส่วน log/สถานะ/ยืนยันวัน rules บังคับ การแก้ข้อมูลผ่าน Firebase Console ข้าม rules ทั้งหมด (รวม audit) เป็นข้อจำกัดของ Firebase
- **ใช้ได้เครื่องเดียวต่อพนักงาน** และ 1 เครื่องต่อพนักงาน 1 คน การผูกเครื่องใช้กุญแจสุ่มเก็บในเบราว์เซอร์ของมือถือ (ไม่มีทางอ่านจากฐานข้อมูลได้) ถ้าพนักงานคัดลอกกุญแจไปเครื่องอื่นได้ต้องเปิด DevTools ซึ่งเกินวิสัยการป้องกันของเว็บ
- **รหัสผ่านสั้น 6 ตัวขึ้นไป (ตัวเลขล้วนได้) และสมัครเปิดอยู่** ใครมี apiKey สร้างบัญชีได้ แต่บัญชีใหม่ไม่ได้สิทธิ์ใดๆ จนกว่าเจ้าของอนุมัติ และเขียนได้เฉพาะคำขอของตนเอง ปิดสวิตช์รับสมัครเมื่อไม่ใช้
- เปิดหน้า master บนมือถือพนักงานได้ (เช่นเพื่อตั้งพิกัดสาขา) master ใช้ตัวตนแยกจากแอปลงเวลา จึงไม่กระทบการผูกเครื่อง

## อัปเดตเวอร์ชัน

แก้ไฟล์แล้ว push ไป `main` หน้า `clock.html` ใช้ service worker แบบเครือข่ายก่อน (รอ 3 วินาที) จึงได้ไฟล์ใหม่ทันทีเมื่อมีเน็ต ถ้าแก้รายการไฟล์ที่ precache หรือไอคอน ให้เพิ่มเลข `CACHE_VERSION` ใน `sw.js` (ปัจจุบัน `clock-v2`)

**ตรรกะกลาง 2 ไฟล์**: บล็อก `SHARED CORE v3` (summarize, dayReport ฯลฯ) ต้องเหมือนกันทุกตัวอักษรใน `clock.html` และ `clock-master.html` ถ้าแก้ ให้แก้ใน `clock-master.html` ก่อน คัดลอกทั้งบล็อกไป `clock.html` แล้วรัน `cd tests && npm run test:core` (ตรวจว่าเหมือนกันและรัน unit test บนโค้ดที่ดึงจากไฟล์จริง)

ค่าคงที่ 16 ชั่วโมง (กะค้าง) และ 30 วินาที (กันกดซ้ำ) ฝังอยู่ทั้งใน `database.rules.json` และ HTML ถ้าจะเปลี่ยนต้องแก้ทั้งสองที่

## ทดสอบ

- เทสตรรกะกลาง/รายงาน/CSV (node ล้วน ไม่ต้องมี emulator): `cd tests && npm run test:core`
- ข้อมูลตัวอย่างสำหรับทดลองรายงาน: `node tests/seed-phase3.mjs` (เขียนลง emulator ผ่าน REST)
- เทสกฎอัตโนมัติ (R1-R77 + ตรรกะกลาง รวม 103 เทส): `cd tests && npm install && npm test` (ใช้ Firebase Emulator ต้องมี Java 17 ขึ้นไป `package.json` ล็อก `firebase-tools@14.27.0` เพราะรุ่น 15 ต้องใช้ JDK 21)
- เช็กลิสต์ทดสอบด้วยมือและเคสสำหรับ Rules Playground: `docs/testing.md`
- รันหน้าเว็บในเครื่องกับ emulator: ดู `docs/testing.md` หัวข้อ "ทดสอบในเครื่อง"
