# ลงเวลา อึ้งลักเส็ง (ระบบลงเวลาเข้า-ออก-พักด้วย GPS)

แอปไฟล์เดียว 2 หน้า ใช้ Firebase Realtime Database และ GitHub Pages ไม่ต้องมี build tool

| หน้า | ใช้โดย | ลิงก์ (หลังเปิด Pages) |
|---|---|---|
| `clock.html` | พนักงาน (มือถือ ติดตั้งเป็นแอปได้) | `https://xziramoon.github.io/ngluckseng-clock/clock.html` |
| `clock-master.html` | เจ้าของร้าน (คอมพิวเตอร์) | `https://xziramoon.github.io/ngluckseng-clock/clock-master.html` |

เฟส 1 (เวอร์ชันนี้): ลงทะเบียนและผูกเครื่อง, กดเข้างาน/พัก/กลับ/ออกด้วยการตรวจตำแหน่ง, หน้าเจ้าของดูสถานะสด จัดการพนักงาน ตั้งค่าสาขา อนุมัติเครื่อง
ยังไม่มี: หน้าตรวจ log ที่ติดธง, แก้เวลา, ประวัติ, รายงาน/CSV (เฟส 2-3)

## ขั้นที่ 0 ตรวจกฎ Firebase เดิมก่อน (สำคัญมาก ทำก่อนเปิด Anonymous)

การเปิด Anonymous Auth ทำให้ใครก็ได้บนอินเทอร์เน็ตมีสถานะ `auth != null` ได้ ถ้ากฎของข้อมูลเดิม (เช่น STOCK MASTER) ใช้แค่ `auth != null` ข้อมูลเดิมจะถูกเปิดให้คนแปลกหน้า

1. Firebase Console > Realtime Database > Rules > คัดลอกกฎเดิมทั้งหมดเก็บสำรองไว้ก่อน
2. ดูที่ระดับบนสุดของ `"rules"` ถ้ามี `".read"` หรือ `".write"` อยู่ตรงนั้น (เช่น `true` หรือ `"auth != null"`) กฎของ attendance จะไม่มีผล เพราะสิทธิ์ของ RTDB ไหลลงไปยังลูกทั้งหมดและเพิกถอนที่ชั้นล่างไม่ได้ ต้องย้ายสิทธิ์นั้นลงไปไว้ที่ node ของข้อมูลเดิมแต่ละตัวก่อน
3. ถ้ากฎของข้อมูลเดิมใช้ `auth != null` ให้เปลี่ยนเป็น
   `auth != null && auth.token.firebase.sign_in_provider !== 'anonymous'`
   ก่อนเปิด Anonymous
4. ห้ามแตะ node อื่นนอกจาก `attendance`

## ติดตั้ง

1. **เปิดวิธีล็อกอิน** Firebase Console > Authentication > Sign-in method > เปิด **Anonymous** และ **Email/Password**
2. **โดเมนที่อนุญาต** Authentication > Settings > Authorized domains > เพิ่ม `xziramoon.github.io` (`localhost` มีอยู่แล้วตามปกติ)
3. **สร้างแอดมินคนแรก** Authentication > Users > Add user (อีเมล + รหัสผ่าน) > คัดลอก **User UID** > Realtime Database > Data > เพิ่ม `attendance/admins/<UID>` = `true` (ชนิด boolean ไม่ใช่ข้อความ) การเขียนใน Console ไม่ผ่านกฎ จึงเพิ่มได้
4. **รวมกฎ** เปิดไฟล์ `database.rules.json` เอาก้อน `"attendance": { ... }` ไปวางเป็นพี่น้อง (sibling) กับ node เดิมใน `"rules"` **ห้ามวางทับทั้งหน้า** แล้วให้ Boss ตรวจก่อนกด Publish
5. **เอา config** Project settings > Your apps > Web app (ถ้ายังไม่มีให้สร้าง) > คัดลอกค่าไปใส่ `FIREBASE_CONFIG` ที่ด้านบนของ **ทั้งสองไฟล์** (`clock.html` และ `clock-master.html`) ต้องมี `databaseURL` ของภูมิภาค เช่น `https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app`
   config ของเว็บไม่ใช่ความลับ สิ่งที่กันข้อมูลคือกฎ (rules) ในข้อ 4
6. **GitHub Pages** Settings > Pages > Deploy from branch `main` / `(root)`
7. (แนะนำ) Google Cloud Console > APIs & Services > Credentials > จำกัด API key ให้ใช้ได้เฉพาะ HTTP referrer `https://xziramoon.github.io/*` และ `http://localhost:*/*`

repo นี้เป็น public อย่าคอมมิตข้อมูลลับอื่นใด (ค่า config เว็บของ Firebase ไม่ถือเป็นความลับ แต่รหัสผ่านแอดมิน/service account ห้ามใส่เด็ดขาด)

## เริ่มใช้งาน

1. เปิด `clock-master.html` > ล็อกอินด้วยบัญชีแอดมิน
2. แท็บ **ตั้งค่าสาขา** > กด "สร้าง 2 สาขาเริ่มต้น" > ไปยืนที่ร้าน เปิดหน้านี้จากมือถือ กด "ใช้ตำแหน่งเครื่องนี้" แล้วบันทึก (หรือวาง "13.xxxx, 100.xxxx" จาก Google Maps) ปรับรัศมีด้วยสไลเดอร์ ค่าใหม่มีผลกับมือถือพนักงานทันที ไม่ต้องรีเฟรช
   - สาขาวงเวียนมีพิกัดหน้าร้านใส่มาให้แล้ว (17.318062, 99.832187 — 59/9 ถ.เทศบาลดำริ 3 สวรรคโลก วัดจาก GPS หน้าร้านจริง; ค่าเริ่มต้นรัศมี 10 ม. ยอมรับสัญญาณ ±30 ม. ชายขอบ x2 = 20 ม.) ตรวจบนภาพดาวเทียมอีกครั้งแล้วกดบันทึกได้เลย ส่วนสาขาแยกคลองยางยังต้องปักเอง
3. แท็บ **พนักงาน** > เพิ่มชื่อเล่น สาขา เวลาเข้ากะ และ PIN 4 หลัก
4. ให้พนักงานเปิดลิงก์ `clock.html` ที่มือถือ > แตะชื่อตัวเอง > ใส่ PIN > รอ
5. แท็บ **รอตรวจ** > ตรวจป้าย "PIN ถูกต้อง" แล้วกดอนุมัติ มือถือพนักงานจะเข้าหน้าหลักเอง

## ติดตั้งบนมือถือ

- **iPhone (Safari)** ปุ่มแชร์ > เพิ่มไปยังหน้าจอโฮม > **เปิดจากไอคอนแล้วค่อยลงทะเบียน** (แอปบนหน้าจอโฮมแยกข้อมูลจาก Safari ถ้าลงทะเบียนใน Safari ก่อน ต้องลงทะเบียนใหม่หลังติดตั้ง)
- **Android (Chrome)** เมนู ⋮ > ติดตั้งแอป

## แก้ปัญหาที่พบบ่อย

- **ตำแหน่งถูกปฏิเสธ** iPhone: การตั้งค่า > ความเป็นส่วนตัวฯ > บริการหาตำแหน่งที่ตั้ง > Safari/เว็บไซต์ > ขณะใช้งานแอป / Android: แตะรูปแม่กุญแจข้างลิงก์ > สิทธิ์ > ตำแหน่ง > อนุญาต
- **iPhone แจ้ง "ตำแหน่งที่แม่นยำ" ปิดอยู่** เปิด "ตำแหน่งที่แม่นยำ" ในการตั้งค่าตำแหน่งของเว็บนั้น
- **เปลี่ยนมือถือ/ล้างข้อมูลเบราว์เซอร์** ต้องลงทะเบียนและรออนุมัติใหม่ เครื่องเก่าจะใช้ไม่ได้หลังอนุมัติเครื่องใหม่
- **พนักงานลืมกดออกงาน** ผ่านไป 16 ชั่วโมงแล้วระบบให้กดเข้างานใหม่ได้ (เจ้าของเห็นป้าย "ลืมออกงาน" ในหน้าสถานะ) การแก้ log ย้อนหลังอยู่ในเฟส 2
- **ทำงานได้กะเดียวต่อวัน** หลังออกงานแล้วเข้าใหม่ในวันเดียวกันไม่ได้

## ข้อจำกัดที่ควรรู้

- **ตำแหน่งปลอมได้**: กฎตรวจไม่ได้ว่าพิกัดเป็นของจริง แอปปลอมตำแหน่ง (mock location) หรือสคริปต์ที่ยิงตรงเข้าฐานข้อมูลอาจผ่านได้ กฎบังคับได้แค่ชนิดข้อมูล ช่วงค่า เวลาเซิร์ฟเวอร์ และระยะที่อ้างต้องไม่เกินรัศมี x ตัวคูณชายขอบของสาขา ส่วนที่เหลือพึ่งธง "น่าสงสัย" กับการตรวจของเจ้าของ
- **วันทำงานเลือกเองได้ (ข้อจำกัดที่ทราบ)**: กฎของ Firebase แปลงเวลาปัจจุบันเป็น "วันที่" ไม่ได้ พนักงานที่แก้โค้ดเองอาจเลือกวันทำงานย้อนหลังหรือล่วงหน้าตอนกดเข้างานเพื่อเลี่ยงกติกา "กะเดียวต่อวัน" ได้ เวลาจริงของ log (ts) ยังเป็นเวลาเซิร์ฟเวอร์เสมอ ในหน้าสถานะวันนี้ของ master จะขึ้นป้ายแดง "วันทำงานไม่ตรงกับเวลาจริง ตรวจสอบ" เมื่อพบกรณีนี้ ให้เจ้าของใช้ ts เป็นหลัก (ดูเทส R23 ใน tests/rules.test.mjs)
- **ใช้ได้เครื่องเดียวต่อพนักงาน** และ 1 เครื่องต่อพนักงาน 1 คน
- เปิดหน้า master บนมือถือพนักงานได้ (เช่นเพื่อตั้งพิกัดสาขา) master ใช้ตัวตนแยกจากแอปลงเวลา จึงไม่กระทบการผูกเครื่อง

## อัปเดตเวอร์ชัน

แก้ไฟล์แล้ว push ไป `main` หน้า `clock.html` ใช้ service worker แบบเครือข่ายก่อน (รอ 3 วินาที) จึงได้ไฟล์ใหม่ทันทีเมื่อมีเน็ต ถ้าแก้รายการไฟล์ที่ precache หรือไอคอน ให้เพิ่มเลข `CACHE_VERSION` ใน `sw.js` (เช่น `clock-v2`)

ค่าคงที่ 16 ชั่วโมง (กะค้าง) และ 30 วินาที (กันกดซ้ำ) ฝังอยู่ทั้งใน `database.rules.json` และ HTML ถ้าจะเปลี่ยนต้องแก้ทั้งสองที่

## ทดสอบ

- เทสกฎอัตโนมัติ: `cd tests && npm install && npm test` (ใช้ Firebase Emulator ต้องมี Java 17 ขึ้นไป `package.json` ล็อก `firebase-tools@14.27.0` เพราะรุ่น 15 ต้องใช้ JDK 21)
- เช็กลิสต์ทดสอบด้วยมือและเคสสำหรับ Rules Playground: `docs/testing.md`
- รันหน้าเว็บในเครื่องกับ emulator: ดู `docs/testing.md` หัวข้อ "ทดสอบในเครื่อง"
